## Run the paced H5 audit

From the task root in PowerShell, use a new output directory for each run. The auditor accepts multiple `--report` arguments and requires exactly one case per report. Example:

```powershell
$taskRoot = (Get-Location).Path
$repoRoot = Join-Path $taskRoot 'work\theEchoChamber'
$reports = @(
  "$repoRoot\work\validation_runs\acceptance-c16c0ee\paced-rule-30min\controller_paced_20261029T215543Z.json",
  "$repoRoot\work\validation_runs\acceptance-c16c0ee\paced-pid-30min\controller_paced_20261029T222708Z.json",
  "$repoRoot\work\validation_runs\acceptance-c16c0ee\paced-esn-30min\controller_paced_20261029T225815Z.json"
)
$args = @()
foreach ($report in $reports) { $args += @('--report', $report) }
$args += @(
  '--source-h5', "$taskRoot\work\tmp\ca3_import_validation\2026_05_29_0001.h5",
  '--raw-abf', "$taskRoot\work\data\CA3_slow_waves\2026_05_29_0001.abf",
  '--output-dir', "$taskRoot\outputs\paced-30min-c16c0ee-audit-rerun"
)
& "$taskRoot\work\venv314\Scripts\python.exe" `
  "$repoRoot\docs\validation\required-runs-c16c0ee\audit-reproduction\audit_final_paced_runs.py" @args
```

The auditor writes `README.md`, `paced_30min_evidence.json`, and `paced_30min_segments.csv` in the selected output directory. Its checks stream the source H5 and raw ABF for SHA-256, read H5 metadata, diagnostic/index/event datasets, and scan `signals/ao_command_V` in chunks. For `signals/ai_raw_V` and `signals/electrode_mV`, it checks dataset shape only; it does not inspect their sample values. It does not parse the ABF signal payload. These checks establish recording structure and provenance, not biological efficacy or physical output.

## Reconstruct the runtime-input comparison

The reconstruction checks all non-`docs/` entries in the manifest against both checkouts. It requires manifest SHA-256 `0c5efa23273fa1bdc13473d142681739c71094af92f32f521fdd21dd24e9572f`, main HEAD `c16c0eee0174c7c016d05a5ce617186a3c4c42d8`, and isolated HEAD `40a77d924a8f4fae45498d86d3667fe1860ecbd9`. It verifies the isolated bytes against the manifest and accepts the main checkout only when bytes match exactly or differ solely by CRLF-to-LF normalization. It fails on missing files, other content changes, revision mismatch, or a different manifest. Git must be on `PATH`. Use disposable clean Windows checkouts at those commits; set `core.autocrlf=true` for the isolated checkout so its working-tree bytes reproduce the tested Windows inputs. Do not reset an active working tree. The output path must not already exist.

```powershell
$taskRoot = (Get-Location).Path
$repoRoot = Join-Path $taskRoot 'work\theEchoChamber'
& "$taskRoot\work\venv314\Scripts\python.exe" `
  "$repoRoot\docs\validation\required-runs-c16c0ee\audit-reproduction\reconstruct_runtime_input_proof.py" `
  --task-root $taskRoot `
  --main-root $repoRoot `
  --isolated-root "$taskRoot\work\control-validation-fixes" `
  --manifest "$repoRoot\docs\validation\required-runs-c16c0ee\audit-reproduction\unit-test-manifest.json" `
  --output "$taskRoot\work\runtime-input-proof-reconstruction-rerun.json"
```

The reconstruction is a new run with a new timestamp and output; it does not replace the preserved result or claim byte identity with the earlier inline execution.
